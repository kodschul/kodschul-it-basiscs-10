# Lab 3.1 - Uebung: Den Weg zur erreichbaren Website planen

## Auftrag

Die Baeckerei-Website soll vom Kursrechner in eine erreichbare Betriebsumgebung
wechseln. Eine Bereitstellungsstrecke erstellen und Verantwortlichkeiten zuordnen.

## Start

Bereit liegen Karten fuer `Website-Dateien`, `Dockerfile`, `Image`, `Container`,
`Port`, `Browser`, `VM`, `Plattform` und `Cloud-Anbieter`.

## Schritte

1. Legt die Karten vom Website-Ordner bis zum Browser in eine sinnvolle Reihenfolge.
2. Markiert, welche Karte die laufende Website darstellt.
3. Ordnet VM, Plattform und fertige Mail-Anwendung IaaS, PaaS und SaaS zu.
4. Notiert fuer eine VM und eine Plattform jeweils eine Aufgabe des Anbieters und des Teams.
5. Erklaert einer Partnergruppe, wie die Website vom Ordner zum Browser gelangt.

## Fertig, wenn

- die Kartenstrecke Website-Dateien -> Image -> Container -> Port -> Browser sichtbar ist,
- die drei Service-Modelle richtig zugeordnet sind,
- Verantwortlichkeiten fuer IaaS und PaaS begruendet sind.

## Hilfe

1. Ein Image ist noch nicht gestartet, ein Container schon.
2. Der Port macht einen Dienst von ausserhalb des Containers erreichbar.
3. Bei IaaS bleibt mehr Betrieb beim Team als bei PaaS.

## Zusatzaufgabe

Nennt eine Pruefung, die vor einem echten Deployment noetig waere, etwa Backup,
Zugriffsrecht oder Test im Browser.
